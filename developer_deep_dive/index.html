    Developer Deep Dive: System Architecture & Core Logic

    This document provides a high-substance technical reference for the GTM Validator. It explains how the system is architected, what each file is responsible for, and dives into the complex logic with actual code references.

    1. System Design: The Data Flow

    The GTM Validator follows a Diagnostic-to-Action lifecycle. Here is how data moves through the system:

    1. Identity: Middleware ensures every visitor has a gtm_client UUID cookie.
    2. Assessment: AssessmentSession collects responses (1-5 scores + text notes).
    3. Aggregation: gtm.services._compute_scores runs a weighted algorithm to generate a maturity rating.
    4. Snapshotted State: Results are frozen into a ResultSnapshot to prevent recalculation lag.
    5. AI Strategy: Background threads kickoff Gemini to write a 30-day playbook based on the snapshot.
    6. Collaborative Execution: Workspace members turn playbook recommendations into ActionItems.

    2. Module Directory: Who Does What?

    gtm/ (Core Assessment Engine)

    • models.py: The "Relational Bible." Defines Categories, Questions, Responses, and the critical ResultSnapshot.
    • services.py: The "Brain." Contains the math for weighted scoring and the logic for safe session retrieval.
    • ai_services.py: The "AI Gateway." Handles interaction with Vertex AI, prompt building, and response sanitization.
    • ai_auditor.py: The "Vision Bridge." Multimodal logic that audits images/PDFs and modifiers the GTM score.
    • views.py: The "Traffic Controller." Manages the multi-step HTMX assessment wizard.
    • middleware.py: Handles anonymous user tracking and persistent identity.

    dashboard/ (Analytics & Assets)

    • analytics.py: Logic for calculating KPI velocity, weekly trends, and workspace-scoped context.
    • document_processors.py: The "Parser." Hybrid PDF/Image OCR engine using local libraries and AI fallback.
    • views.py: Manages the Kanban task board, asset library, and KPI gap reporting.

    3. Core Logic Deep Dives

    A. The Weighted Scoring Algorithm

    The maturity score isn't a simple average. It uses two tiers of weights defined in the load_gtm_defaults command.

    # gtm/services.py (simplified logic)
def _compute_scores(session):
    # Tier 1: Question weights (e.g. ICP is 1.25, Testimonials are 0.95)
    category_avg = sum(score * question_weight) / sum(question_weights)

    # Tier 2: Category weights (Demand 40%, Conversion 40%, Delivery 20%)
    overall_score = sum((category_avg / 5) * (cat_weight / total_weight) * 100)
    return overall_score

    B. Resilient AI: The "Rescue" Pattern

    Vertex AI sometimes returns malformed JSON or markdown-wrapped strings. The project uses a regex-based discovery engine to "rescue" the content.

    # gtm/ai_services.py
def _normalize_ai_playbook_markdown(playbook_text):
    # Regex fallback: extract content of "markdown_playbook" key if json.loads fails
    match = re.search(r'["\']markdown_playbook["\']\s*:\s*["\'](.*?)(?:["\']\s*,\s*["\']|["\']\s*}|$)', 
                      src, re.DOTALL)
    if match:
        src = match.group(1)

    # Clean up LLM artifacts (\n, \", etc)
    return src.replace('\\n', '\n').replace('\\"', '"').strip()

    C. Multimodal Vision-to-Scoring Bridge

    The ai_auditor turns qualitative critiques into quantitative score modifiers.

    # gtm/ai_auditor.py
def _extract_score_modifier(audit_text):
    # Regex looks for "Evidence Score: N/10" in the AI's prose
    match = re.search(r"evidence\s+score[:\s*]+(\d+(?:\.\d+)?)\s*(?:/\s*10)?", audit_text, re.I)
    if match:
        score = float(match.group(1))
        # Map 1-10 scale to -3 to +3 GTM score modifier
        if score <= 3: return -3
        if score >= 7: return 3
        return 0

    D. Multi-Tenant Isolation

    Security is enforced by scoping every query to a Workspace while maintaining a fallback for personal assessments.

    # dashboard/analytics.py
def get_dashboard_context(request, current_workspace, ...):
    if current_workspace:
        # Strict workspace isolation
        assessments_qs = AssessmentSession.objects.filter(workspace=current_workspace)
        action_items_qs = ActionItem.objects.filter(workspace=current_workspace)
    else:
        # Fallback to private user data
        assessments_qs = AssessmentSession.objects.filter(user=request.user)

    4. Performance Standards: Query Bounding

    The results page is complex but stays fast because of a strict "Query Bounding" rule verified in gtm/tests.py.

    # gtm/tests.py
def test_results_performance(self):
    with CaptureQueriesContext(connection) as ctx:
        response = self.client.get(reverse('gtm:results', args=[self.session.uuid]))
        # Guardrail: A 36-question assessment must not trigger > 30 queries
        self.assertLessEqual(len(ctx), 30)
    This is achieved by Prefetching categories and tool recommendations in bulk at the start of the view request.
