    Collaborative Workspaces & RBAC

    The GTM Validator implements a multi-tenant workspace architecture designed for team collaboration, as seen in gtm/models_workspace.py and gtm/views_workspace.py.

    1. Soft Isolation Pattern

    Rather than a strict hard-tenant database split, the project uses a "Soft Isolation" pattern: - AssessmentSession Ownership: Sessions can be owned by a User (private) or a Workspace (team-shared). - Context Filtering: The get_dashboard_context utility in dashboard/analytics.py dynamically builds query filters based on the current_workspace. If a workspace is active, all private user data is automatically excluded from the analytical views.

    2. Role-Based Access Control (RBAC)

    The system defines a granular permission set through the WorkspaceMembership model:

    Role Internal Permission Logic
    admin Full CRUD on workspace settings, members, and all assessments.
    manager Can start assessments and create/assign ActionItem tasks.
    contributor Can edit assessments and update assigned tasks.
    viewer Read-only access to snapshots and analytics.
    funti3r_consultant Specialized external role with audit-specific visibility.

    3. Centralized Authorization (safe_get_session_or_403)

    The project avoids duplicating permission checks in views by centralizing them in gtm.services.safe_get_session_or_403. - The Protocol: 1. Fetch the session via UUID. 2. Check if session.user == request.user. 3. If not, check if session.workspace exists and if the request.user has an active WorkspaceMembership there. 4. Log any unauthorized access attempts with detailed metadata for security auditing.

    4. Invitation Lifecycle

    Collaborative growth is managed via token-based invitations: - Token Generation: uuid4 tokens are used to create unique invitation links. - Expiration: Invitations are checked against timezone.now() to ensure they are accepted within the allowed window (typically 7 days). - Claiming: Upon acceptance, the system automatically creates the WorkspaceMembership record and transfers any pending tasks to the new user's profile.

    5. Shared Resource Auditing

    In a workspace context, the AI Auditor (gtm/ai_auditor.py) can audit shared resources (dashboard.Resource). - Mechanism: The audit critique is stored at the workspace level, creating a shared "Strategic Knowledge Base" where all team members can see the AI's feedback on company assets.
