    Maintenance & Operational Tools

    The GTM Validator project includes several custom management commands in gtm/management/commands/ that encapsulate critical "tribal knowledge" for system maintenance and initialization.

    1. Framework Initialization (load_gtm_defaults)

    This is the most critical command for setting up a new environment. - The Data Structure: It contains a massive hardcoded dictionary of Categories (Demand, Conversion, Delivery), Questions (D1-D12, C1-C12, etc.), and Recommendation Bands. - Logic: It uses get_or_create to ensure the diagnostic framework is present in the database without duplicating existing data. It also populates the ai_metadata field which is essential for Gemini's reasoning.

    2. Recommendation Seeding (load_tool_recommendations)

    This command seeds the "Software Matchmaking" engine. - Keyword Matching: It maps specific GTM keywords (e.g., "CRM", "SEO", "Attribution") to recommended software tools and descriptions. - Categorization: Every recommendation is linked to a Category (e.g., HubSpot linked to "Demand" and "Conversion").

    3. Data Migration Tools

    backfill_owners

    A legacy maintenance tool used during the transition from a purely anonymous session model to a workspace-aware model. - Logic: It identifies AssessmentSession records without an explicit user or workspace and attempts to map them based on the owner_client_id cookie history.

    4. Asynchronous AI Monitoring

    While not a standalone command, the utils_ai_monitoring.py (if available) provides the backend for tracking AI usage across these operations. - Usage Tracking: Every call to Gemini (from a view or a command) is logged with token counts to AIUsageTracker. - Quota Guard: This data informs the _quota_cooldown_active logic to prevent exceeding Vertex AI API limits during batch operations.
