    GTM Validator: High-Context System Design

    This document maps the business goals of the platform to the technical implementation. It provides the "Substance" for how each part of the codebase enables the project's vision.

    1. The "Resilient Consultant" Architecture

    The core challenge of the GTM Validator is providing always-on strategic advice while relying on external AI APIs that can be slow or unavailable.

    Goal: Zero-Downtime Strategy

    Even if Google's Gemini API is down, the user must receive value. - Implementation: gtm/ai_services.py uses a Static-Fallback Pattern. - Context: If ResourceExhausted is caught, the system sets a cache-based "Quota Cooldown" and serves high-quality, pre-written advice from the RecommendationBand model.

    2. The "Modern Monolith" UI Strategy

    We avoided the complexity of a separate React/Vue frontend to keep the AI-to-UI feedback loop as tight as possible.

    Goal: Single-Page Experience without JS Overhead

    The assessment wizard must feel like a modern app but remain fast and SEO-friendly. - Implementation: gtm/views.py uses HTMX with the HX-Request header check. - Context: The view detects if it's an partial update and returns only the form segment, saving bandwidth and improving perceived performance.

    3. The "Snapshot" Integrity Model

    GTM strategy changes quarterly. A report from January should not change if the diagnostic questions are updated in March.

    Goal: Strategic Immutability

    Ensure that historical reports are preserved exactly as they were generated. - Implementation: gtm/models.py defines the ResultSnapshot record. - Context: Instead of linking to current Question objects, the snapshot stores a JSON-denormalized copy of all weighted scores and AI text at the time of completion.

    4. Multi-Tenant "Soft" Isolation

    The platform needs to support team collaboration while allowing individual users to have private assessments.

    Goal: Secure but Collaborative

    • Implementation: The safe_get_session_or_403 service in gtm/services.py.
    • Context: This function implements a hierarchical check: (1) Does the user own it? (2) If not, is the user a member of the Workspace that owns it? (3) Is their role high enough? This centralizes security logic in one place.

    5. Token-Aware Analytics

    AI cost management is critical for a SaaS product.

    Goal: Cost Transparency

    • Implementation: gtm/utils_ai_monitoring.py.
    • Context: Every AI call logs tokens used to the AIUsageTracker. This allows administrators to see exactly which features (Playbook vs. Chat) are driving costs and set proactive rate limits.
