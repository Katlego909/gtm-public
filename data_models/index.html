    Data Models: Relational Schema & State Management

    The Big Picture

    The data model is built for Historical Accuracy and Multi-Tenancy. We use the "Snapshot Pattern" to ensure that once an assessment is completed, the results are frozen. This prevents a company's historical report from changing if you later update the diagnostic questions in the Django Admin.

    1. Core Relationship Diagram

    The assessment engine relies on a hierarchical structure:

    • Category: The high-level GTM pillars (Demand, Conversion, Delivery).
    • Question: The diagnostic units. Each carries ai_metadata for LLM context.
    • AssessmentSession: The container for a single company's checkup.
    • Response: The bridge between a session and a question, storing the 1-5 score.

    Critical Model: ResultSnapshot

    The ResultSnapshot is a one-to-one record with an AssessmentSession. It acts as the "Frozen State" of a completed assessment.

    class ResultSnapshot(models.Model):
    session = models.OneToOneField("AssessmentSession", on_delete=models.CASCADE)
    overall = models.FloatField() # Weighted total
    category_breakdown = models.JSONField() # Cached radar chart data
    ai_playbook = models.TextField() # The final Gemini strategy
    report_sent = models.BooleanField(default=False)

    2. Workspace & RBAC Architecture

    The platform uses a "Soft Tenant" model for collaboration.

    • Workspace: The top-level organization container.
    • WorkspaceMembership: Links a User to a Workspace with a role.
    • Roles: admin, manager, contributor, viewer, funti3r_consultant.

    Permission Scoping

    Permissions are not hardcoded in views. They are enforced via the safe_get_session_or_403 service.

    # gtm/services.py
def safe_get_session_or_403(request, session_id):
    session = AssessmentSession.objects.get(uuid=session_id)
    # 1. User owns it personally
    if session.user == request.user: return session
    # 2. User is part of the workspace that owns it
    if request.user in session.workspace.active_members: return session
    # 3. Deny access
    raise PermissionDenied

    3. Collaboration & Action Models

    The "Execution" phase of the GTM lifecycle is managed by task models:

    • ActionItem: A specific task (e.g., "Refine ICP").
    • ActionItemComment: Threaded team communication.
    • GTMFile: Binary strategic evidence with AI audit metadata.

    The "Vision Bridge" in Models

    The GTMFile model includes fields that store AI-calculated modifiers.

    class GTMFile(models.Model):
    # stores "Evidence Score: 8/10"
    ai_audit_notes = models.TextField()
    # stores +2 (added to GTM score)
    ai_audit_score_modifier = models.IntegerField(default=0)
